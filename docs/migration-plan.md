## 实際字段映射草案

以下新对象是设计名，尚未创建表。

| 旧来源 | 新对象 | 转换/核验 |
|---|---|---|
| members.id/phone/nickname/created_at | customers + legacy_mappings | 保留来源标识；业务客户不自动成为可登录用户；不按电话自动认领/合并 |
| members.balance | wallet_accounts / opening entries | REAL 转精确十进制再转整数分；不直接浮点乘100；超出分精度或负值进入异常；来源不清禁止全部算成本金 |
| recharges.id/member_id/amount/note/created_at | 历史充值记录或经核验资金流水 | 旧表没有渠道、赠送分桶、核实人；保留未知，禁止伪造微信到账 |
| orders.guest_* / member_id | orders + customer relation | 空会员关联不等于无客户；未知归属进入人工映射队列 |
| orders.pet_* / preinspect_json | 历史宠物快照，核验后 pets / service_records | 同名宠物不得自动视为同一只；年龄/疫苗为当时快照，不推断现在状态 |
| orders.services_json | legacy items / order_items snapshots | 校验JSON、金额与总额；无法识别项目保留原来源，列异常 |
| orders.total_amount / deducted_from_balance / payment_method | 历史应收与余额消费证据 | 并非渠道真实到账证明；无法补出原退款、组合支付和本金赠送来源 |
| orders.created_at | occurred_at 原始证据 | 旧函数生成ISO时间；验证实际字符串，异常保留原值，显示采用门店时区 |
| service_catalog.id/name/price/sort_order | services + price versions | 老板批准现行价目后启用；历史成交价不随新价目变化 |

## 下一阶段操作顺序

1. 核实最终源目录与旧端是否仍写入。当前存档可只读；正式切换前若运行中用一致性备份机制，若暂停写入则连同必要 WAL 等取得完整快照。不得任意只拷活库主文件。
2. 在受控且被 Git 忽略的位置建立工作快照，记录源/副本校验和、版本与批次；不在原始备份执行 SQL 迁移或初始化。
3. 建来源映射 `(legacy_source, table, legacy_id)` 唯一约束。迁移批次记录源 hash、转换版本、成功/异常数量。每次重跑不得重复客户或开账余额。
4. 老板确认唯一旧账户及订单真实/演示性质、是否还有线下余额。数值重建一致只是辅助证据；核验明细私下查看，Git 只存脱敏计数及测试资料。
5. 用完全虚构数据试迁移并验证空值、同号客户、同名宠物、异常金额、重跑幂等和失败回滚；再对授权工作副本做脱敏映射预演。
6. 钱包二选一且不能双计：可靠全历史可重建则导入核验流水；仅期初余额可核验时记一笔有来源的开账流水，旧明细保留只读历史，不再重复加到余额。本金/赠送无法确定的账户暂缓启用。
7. 输出逐账户差异、总额及记录数核对，老板签认后安排最终快照/导入/抽查。不存在的履约、寄养、接送状态用“历史未记录”，不能自动写“已交还”。

## 切换与回退

真实上线前明确停旧端写入时点、导入批次、责任人、恢复目标。新旧不双写。正式 SQL 迁移进入版本控制，禁止 schema push 当生产迁移。

未产生新交易时可按演练恢复旧快照；产生新交易后必须先保全增量和媒体、核对所有资金、再执行受控回退，不能覆盖新流水。应用版本回滚与数据库版本兼容性单独验证。
