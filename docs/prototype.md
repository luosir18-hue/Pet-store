# 五页原型试用说明

启动：在 E:\Pet-store 执行 `node scripts/serve-prototype.mjs`，本机打开 http://127.0.0.1:4173 。没有依赖安装步骤。服务仅监听本机，手机排版按钮用于电脑上预览窄布局，不代表手机已经能联网访问。停止服务在启动终端按 Ctrl+C。

这是虚构数据低保真原型：无共享数据库、无登录鉴权、无业务API、无支付和通知；手机测试版已增加本浏览器localStorage保存，刷新保留已保存进度，不同手机不互通，无法作为真实账目备份。导航允许评审人看不同角色的页面样式，不是实际权限系统。PWA缓存、桌面入口与独立HTTPS部署步骤见[手机测试部署说明](mobile-test-deployment.md)。

## 建议老板试五个操作

1. **今天工作台 → 打开订单**：豆包、糯米的资料和项目已经带出；分别开始/完成，观察还有哪只未完成。是否能少问、少切页面？
2. **单页订单 → 核实并登记收款**：不勾选无法确认，可返回核对；完成后显示演示人工收款，服务和交还不变。是否看得出还欠多少、宠物是否已交还？
3. **客人预约**：输入虚构宠物称呼，选寄养才出现离店日期；选往返才出现两个交接地点；提交显示待老板确认，再点去老板工作台查看。是否知道这是申请而非成功预订？
4. **寄养排期**：猫舍尝试延至17日会因后续预订失败，原16日离店保留；犬舍可演示无冲突延住；照护必须实际填写虚构情况，不默认正常。
5. **接送任务**：去程依次出发、接宠、送达，返程仍待安排。两段不同日期、地址和执行人；正式版只给执行人自己的任务资料。

报价160元、两笼位、时间范围、示例称呼等全为演示设定。不得把它们复制成营业规则。原型只验证关键交互，暂未覆盖新增真实客户、改价、退款、照片上传、真机输入和后台并发。

## 与正式产品的差别

正式版按角色提供各自导航，不向客人开放老板/接送页面。客户联系方式按实际用途收集，旧档案认领须验证；这里省去电话，避免评审时录入真人资料。预约的宠物种类、每只不同服务/注意事项、各段接送日期/联系人在正式版使用结构化档案与任务表单。

原型寄养只比较简单日期边界，不代表已实现实际容量、清洁缓冲、晚退占用和 PostgreSQL 约束。原型收款只提供全额人工确认，不代表会员、支付或完整日结已实现。

反馈只需记：在哪一页、想完成什么、哪里看不懂/重复填、实际应该怎样处理。完整业务验收和真实手机微信内置浏览器试用留到后续阶段。
