## 三、必须守住的设计边界

只做单店、响应式网页优先，后续微信小程序共用后台接口、业务规则、数据库和稳定内部 ID。不要承诺网页一键转小程序，不建设 Electron/SQLite 双向同步、微服务、连锁多租户、积分商城或自动路线优化。

预约申请与已确认分开；真实容量未明确时不能承诺可订。寄养延住重新查资源。往返接送拆成可独立安排人员、时间、地址和状态的两段。每只宠物有独立的服务/寄养记录。

金额以整数分记录，储值本金与赠送分开；收款、消费、退款和应收调整可追溯；资金和资源变更要求事务、幂等、并发测试。不要把订单完成、宠物交还和收款成功混成一个状态。

客户档案不是登录身份。不允许只输入手机号就查看历史或余额，不自动合并同号老档案。客户、员工、司机的对象权限由服务端检查，照片和导出同样受控。

付款截图不是自动到账凭证，人工核销不冒充平台 API 成功。微信、短信、支付、美团和抖音按实际主体与权限核查；无权限时保留真实可用的人工流程。不得使用绕过授权的抓取或模拟登录。
